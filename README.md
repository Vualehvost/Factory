# Завод роботов: алгоритм управления производством

Решение для соревнования по управлению виртуальным заводом. Реализовано на C# (.NET 10) с использованием ASP.NET Core Minimal API.

Сервис принимает события от арены, управляет закупками, станками, складом и продажами, а также ведет байесовскую оценку скрытых предпочтений покупателей.

## Краткое описание стратегии

Основная цель — максимизация прибыли за смену. Алгоритм разделен на три ключевых блока:

1. Байесовская модель покупателей (Hypothesis Elimination).
Вместо слепого перебора алгоритм поддерживает для каждого покупателя набор из 6 гипотез идеального робота (цвет + ручки) с ценовыми границами P_max в диапазоне [45, 75] и коэффициентом f в диапазоне [0.30, 0.60].
- Отказ по цене M сужает верхнюю границу цены.
- Успешная продажа отсекает ложные гипотезы и позволяет вычислить точный образец и максимальную цену за 2-4 сделки.

2. Адаптивное ценообразование.
- Если образец неизвестен, алгоритм использует бинарный поиск по цене (с шагом вниз на 2.5% для компенсации случайного разброса ±2%).
- При наличии нескольких свободных покупателей робот предлагается тому, кто даст максимум ожидаемой прибыли (с учетом ценности разведки).

3. Планирование конвейера (Bottleneck Scheduling).
- Учитывая, что покраска и сборка занимают по 3 такта, они являются узким горлышком. Алгоритм отдает им высший приоритет.
- Выбор цвета и наличия ручек для корпуса определяется динамически на основе того, какие комбинации сейчас в дефиците и принесут максимальную прибыль.
- Встроенная защита от переполнения склада: неликвидные предметы и лишнее сырье утилизируются, чтобы не платить штрафы за хранение.

## Архитектура

- Program.cs — настройка HTTP-сервера, CORS (для песочницы), маршрутизация API.
- Models.cs — DTO-классы для сериализации/десериализации JSON-протокола арены v1.
- Engine.cs — ядро алгоритма: модель знаний о покупателях, логика принятия решений, менеджер состояний прогонов (изоляция по runId, идемпотентность по seq).

## Инструкция по запуску

### Локальный запуск

Убедитесь, что у вас установлен .NET SDK 10.0 или выше.

Выполните следующие команды в терминале:

git clone https://github.com/ваш_ник/Factory.git
cd Factory
dotnet run -c Release

Сервис будет доступен по адресу http://localhost:4001 (или на порту из переменной окружения PORT).
Проверка работоспособности: GET-запрос на http://localhost:4001/v1/health (должен вернуть {"status":"ok"}).

### Запуск для соревнования (в интернете)

Для арены требуется публичный адрес (localhost не принимается). Мы используем Render (Docker):
1. В Program.cs сервис слушает переменную окружения PORT, выдаваемую платформой.
2. В корне лежит Dockerfile для сборки образа.
3. При деплое на Render автоматически разворачивается контейнер с API, готовый к приему событий от арены.

Резервный способ для тестов — запуск локального туннеля: cloudflared tunnel --url http://localhost:4001 --protocol http2.

## Реализованные методы API

- GET /v1/health — проверка доступности.
- GET /v1/info — информация о решении.
- POST /v1/runs/{runId}/start — инициализация прогона, сохранение конфигурации мира.
- POST /v1/runs/{runId}/event — обработка событий (supply, machine_done, sale_result, idle) и выдача команд.
- GET /v1/runs/{runId}/debug — выдача текущих ценовых вилок (low/high) для визуализации в песочнице.
- POST /v1/runs/{runId}/finish — завершение прогона и сбор статистики.
